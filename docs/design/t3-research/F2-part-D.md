## D1. Reading the Claude desktop app's session list (what "sessions" Fjord knows)

2. Mechanism: read-only parse of the Claude desktop app's private files, "Nothing here is a public API" (Claude.swift:5).
   - Dir `~/Library/Application Support/Claude/claude-code-sessions/**/local_*.json` (Claude.swift:74-76, SessionReader 166-196). Decoded fields: `sessionId` (must start `local_`), `cliSessionId`, `title`, `cwd`, `originCwd`, `gitAnchorsFolderRealpath`, `isArchived`, `completedTurns`, `createdAt`, `lastActivityAt`, `lastFocusedAt`, `latestUserFrameAt`, `postTurnSummary{status_category,status_detail}`, `postTurnSummaryFor`, `lastAssistantUuid`, `sshConfig.sshHost` (Claude.swift:105-128, 130-158). Scratch chats = cwd containing `/Claude/scratch-workspaces/` (:136). The Claude-app id `local_<uuid>` is the Fjord thread id; `cliSessionId` is the Claude Code id.
   - "running" is a heuristic: app running AND no current post-turn summary AND last user frame < 2 h old (`runningTimeout`, Claude.swift:78, 146-148); recomputed every read (:180-186). Overridden by the plugin presence file's `turn` field when fresh (ClaudeFeed.applying, Claude.swift:1193-1199).
   - Sidebar unread blue dots: LevelDB (Chromium Local Storage) key `epitaxy-unread-v1` in `~/Library/Application Support/Claude/Local Storage/leveldb`, parsed by a hand-written LevelDB reader (Claude.swift:944-967; LevelDB.swift whole file; dir Claude.swift:77).
   - Watching: FSEvents on `Claude.sessionsDir` (Store.swift:694-696), on Local Storage leveldb with 2 s latency (:698-700), on `~/.claude/projects` with 0.5 s latency filtered to working/background-task sessions (:704-707; Claude.swift:204-205). Plus NSWorkspace launch/terminate/activate notifications filtered by bundle id `com.anthropic.claudefordesktop` (Store.swift:592-594, 718-720; Claude.swift:73), screens sleep/wake notifications (Store.swift:722-735), and one clock timer for the 2 h/30 min expiries (`scheduleClaudeTick`, Store.swift:740-773).
3. Direction/payload: Claude files -> Fjord only; reads on a serial queue `fjord.claude` (Claude.swift:1072), coalesced; mtime-cached per file (:166-196). Frontmost detection = `NSWorkspace.frontmostApplication` == Claude bundle id (Claude.swift:90-92), used to infer "the session you are viewing" = most recently focused (Agents.swift ingest ~line 410).
4. Failure modes: directory missing -> `claudeLink = .missing`; files exist but none decodable -> `.unreadable` (Claude.swift:166-196, 1262-1286 region `read(full:)`; Agents.swift:367-372). UI texts: "Open the Claude desktop app once" / "The app's session format changed" (ClaudeLinkStatus.swift:10-11). DEVELOPMENT.md:179 "when a Claude update changes them, the Router says so and Triage keeps working."
5. Constraints recorded: sessions have "no switch of their own: they follow" the Router toggle (Store.swift:~632 comment); Router cannot be switched on without Claude installed ("Needs the Claude desktop app", SettingsView.swift:401-405; Onboarding.swift:46-52; `Claude.isInstalled` = bundle id registered OR sessions dir exists, Claude.swift:80-83). ## D2. Reading what a working session is doing (transcripts in ~/.claude/projects)

1. User sees: per-row "doing" text ("Editing X", "Running …", "Thinking", "Writing"), todo progress (done/total, in-progress item), latest narration, "waits for you" (question / plan / permission) on running sessions, and background subagents/commands still running after the turn (Router rows: RouterView.swift:621-624; Claude.swift:313-418).
2. Mechanism:
   - Transcript file `~/.claude/projects/<project>/<cliSessionId>.jsonl` located by scanning each project dir (Claude.swift:204-205, 304-310). Only the last 96 KB is read (`tail`, :312-318); lines parsed as JSON with `type` assistant/user, `message.content[]` parts `tool_use` / `tool_result` / `text`, `timestamp`, `message.stop_reason` (`end_turn`/`stop_sequence`) (:327-419, 538-552). Tool names Fjord understands by name: Bash, Edit, MultiEdit, NotebookEdit, Write, Read, Grep, Glob, Agent/Task, WebSearch, WebFetch, TodoWrite, AskUserQuestion, ExitPlanMode, Skill, `mcp__*` (describe(), :555-584). `AskUserQuestion`/`ExitPlanMode` as last tool_use = session "waits for you" and carry `toolUseID` (:347-352) which ties to the form Fjord's hook holds for the same call.
   - Permission prompts of ordinary tools: Fjord's hook (installed in ~/.claude/settings.json, see covered Forms files) drops a note `<session>-<ms>-<pid>.json` in `RouterPaths.permissions` with `tool_name`, `tool_input`, `tool_use_id`, `created_at` (Claude.swift:442-456). Fjord matches it to an open `tool_use` without a `tool_result` in the transcript (walking the file backward in 1 MB chunks if the call is outside the tail, :394-418, 497-513) -> activity "Asks your OK to run `…`" (permissionText, :515-537). Claude Code emits no event when a prompt is approved, so for Bash prompts Fjord watches the Claude Code process itself: `~/.claude/sessions` registry -> pid, then libproc `proc_listpids`/`proc_pidinfo`, `KERN_PROCARGS2`, and kqueue-like `DispatchSource.makeProcessSource` (.fork/.exec/.exit) to detect the approved command starting as a direct child whose argv is `<shell> -c '… && eval '<command>' < /dev/null && …'` (Claude Code's Bash wrapper) (ClaudeProcesses.swift:1-153; Claude.swift:211-262). Notes with no live registry process are deleted (`pruneNotes`, Claude.swift:225-246).
   - Background tasks: `/private/tmp/claude-<uid>/<project>/<cliSessionId>/tasks/<id>.output` (symlink to subagent transcript, or file a shell command writes) (Claude.swift:432 region `tasksRoot`, 633-639), subagent title from `<agent transcript>.meta.json` `description` (:882-886), end announced by `<task-id>…</task-id>` text in the parent transcript (:872-880), command title found via "…with ID: <id>." tool_result (:889-905). Running shell commands detected by walking all of this user's processes' open file descriptors (`proc_pidfdinfo` PROC_PIDFDVNODEPATHINFO) for paths under that root (`openTaskOutputs`, :740-756). Subagent presumed dead after 30 min without transcript write (:~640 `agentTimeout`).
   - Plugin presence files (`RouterPaths.pluginSessions`) read by `ClaudePlugin.live` (covered file) give `turn`, `capabilities`, `pid`, `startedAt`, lease renewals (10 s heartbeat) and override "running" (Claude.swift:1083-1199).
3. Direction/payload: Claude Code files/process table -> Fjord; read-only. Activity reads happen on file events (0.5 s) for working sessions only; reads of tasks "every half second" while sessions work (Claude.swift TaskFolderReader comments).
4. Failure modes: unreadable task folder = "not known" rather than "none" (Claude.swift:~640-660); a note whose call has its result is deleted; sessions resumed under another process get re-watched (:211-222 region).
5. Constraints: DEVELOPMENT.md:179 "None of these is a public API". Needs Claude Code's `AskUserQuestion`/`ExitPlanMode`/`TodoWrite` tool names, the `~/.claude/projects` layout, the `/private/tmp/claude-<uid>` tasks layout and the Bash wrapper's `eval` shape; all would be provider-specific in a T3 rebuild.

## D3. Delivering the user's words into a local session, including waking an idle/asleep one (RouterCarry + RouterSender)

1. User sees: a reply armed on a thread goes "to that thread: its session on this Mac through the signed plugin" (DEVELOPMENT.md:93-95); the pill shows stages "preparing", "sending", "opening <title>" (RouterDispatcher.swift:752-754; RouterRun.swift:540); message arrives in the session as the user's own message. Errors: "Fjord's plugin isn't running in that session: restart it or run /reload-plugins in it; nothing was sent" (RouterRun.swift:405); "It may not have arrived: … Fjord won't send it again by itself" (RouterCarry.swift:229-231 `unsure`).
2. Mechanism (Sources/RouterCarry.swift, RouterRun.swift:317-444; design docs/design/claude-channel.md referenced at RouterCarry.swift:3):
   - Fjord signs the body with a per-install HMAC key (`RelaySigner.sign`/`signCarry`, key `paths.relayKey`, loaded via `RelayKeyCache`; SessionControl.swift whole; Router.swift:316-331) and drops it as a file into the target's inbox folder `RouterPaths.relay/<cliSessionId>/` via `RelayInbox` (ClaudePlugin.swift, covered). The target's own Fjord Claude Code plugin verifies signature/nonce, injects the text as the user's own turn, and writes an answer file (`ok …`, `refused: …`) next to it (RouterCarry.swift:3-11, 215-221).
   - Three plans (RouterCarry.plan, :105-110): `.direct` (target's plugin is up; no other carrier can carry) = write into the target's own inbox; `.carry([carriers])` = give a signed "carry" order to ANOTHER session's plugin, which hands Fjord's signed message to "the app's own send tool (no model turn)", and the Claude desktop app "starts a sleeping session with the message as its first prompt, or hands it to a running one" (RouterCarry.swift:3-8). This carrier path is the actual wake/cold-start mechanism today. Carrier = a local session with Fjord's plugin up with capability `ClaudePlugin.carryCapability` whose `~/.claude/sessions` registry entry has `entrypoint == "claude-desktop"` (carriers(), :84-100); idle before busy, then most recently active; up to 2 carriers tried (`attempts`, :75). `.open` = no carrier and target not up: `Claude.open(local)` = open `claude://claude.ai/epitaxy/<local_id>` (D5), then poll for the target's plugin presence (60 s), then deliver direct.
   - Completion signalled only by files: carrier's `taken` marker (6 s to appear else the order is withdrawn by writing `withdrawn`), carrier ack `refused:`/`unsure:`, then target ack `ok`. Total waits: 45 s running target, 90 s cold start (`asleep`), 60 s opened (Waits, :56-68).
   - Each message becomes a persisted `DeliveryOperation` (nonce, target cli, bodyHash, state waiting/sent/unsure/refused/needsYou, route carried/direct/opened, carrier) saved to disk BEFORE anything is ordered; a quit mid-send is reconciled at next launch from leftover answer files; never re-ordered by Fjord itself (RouterRun.swift:381-396; RouterCarry.swift:337-372 `settleLostOperations`).
   - Gate: `tools.approveSend` and a `gate` closure re-checked right before each file is placed (Router still on, ticket live, not cancelled) (RouterRun.swift:370-375, 393-394).
   - Local-only guard: the Claude-app id must start `local_`; otherwise "That session isn't one of the Claude app's, so Fjord can't send to it" (RouterRun.swift:377-379). Computer (remote) sessions branch to `GuestRouterRuntime.deliver` instead (RouterRun.swift:335-364; covered by other slices).
3. Direction/payload: Fjord -> session; payload is the user's text wrapped in a signed header (`RelayInbox.header(of:)` gives `target` cli id and `nonce`); idempotent by nonce (target plugin "claims" it, RouterCarry.swift:36-38). Answer evidence is the target plugin's file, "not the app's receipt" (:7-8).
4. Failure modes: no key / Router off -> "The Router is off"; carriers all refuse -> "No session in the Claude app could carry the message (…); nothing was sent" (RouterCarry.swift:325); no plugin answer within window -> `.unsure`; cold target never comes up -> `.needsYou` "open it in the Claude app, then send it again" (:138-141); Stop mid-delivery -> refused if nothing placed else unsure (:312-316).
5. Constraints: "A session with a process but no plugin up reads the message as a peer's: it never goes to one." (RouterRun.swift:403); "Sessions already open pick the plugin up once restarted, or after /reload-plugins" (DEVELOPMENT.md:181; SettingsView.swift ~420); requires at least one OTHER live Claude-app session with the plugin to wake a sleeping one, else falls back to opening the session in the desktop app (D5). docs/design/session-wake.md (status: proposal, 2026-10-22) documents why: the Claude app caps CLI processes (`max(6, RAM/3 GB)`, 21 on that Mac), opening a session is only a "warm" start that yields at the cap, only a user send ("KI.sendMessage", cold-starts the CLI with `--resume`) always goes ahead; `claude://code/new?q=` starts a NEW session after the user presses Send; "There is no local API, AppleScript, XPC or watched folder" (session-wake.md:30-47). Its relay-session design (signed `fjord-wake` token, hooks `UserPromptSubmit`, `claude://code/new?q=`) is a PROPOSAL; Sources has no `code/new` hit (grep), so INFERRED not implemented; the shipped answer is the RouterCarry carrier.

5. Constraints: deep-link format is undocumented/private; focusing/opening the session is the only "show me" Fjord does.
