## 1. THE PLUGIN (the main Claude dependency)

### 1.1 What the user sees
- Settings → Router switch ("Needs the Claude desktop app" and the switch is disabled when `!Claude.isInstalled`; `SF/SettingsView.swift:400-410`). Info text states: messages reach sessions "through Fjord's Claude Code plugin"; forms "need a hook in Claude Code's settings (`~/.claude/settings.json`)"; turning the Router off removes the hook and the plugin (SettingsView.swift:406).
- If a running session started before the plugin existed: error "<title> started before Fjord's plugin was installed: restart it or run /reload-plugins in it" (`SF/RouterMCP.swift:991`); and "Fjord's plugin isn't running in that session: restart it or run /reload-plugins in it; nothing was sent" (`SF/RouterRun.swift:524`). Plugin not installed: "Fjord's plugin isn't installed in Claude Code, so nothing can be sent (Settings → Router)" (RouterMCP.swift:985).
- Off-but-removal-failed state stays visible with retry (SettingsView.swift:~411, `store.routerRemovalError`).

### 1.2 Mechanism: it is a Claude Code "hooks module" plugin, NOT settings.json hooks
- Plugin folder written by Fjord: `~/Library/Application Support/Fjord/claude-plugin/` (`RouterPaths.plugin`, `SF/Forms.swift:20`) containing (`SF/ClaudePlugin.swift:57-63`): `.claude-plugin/plugin.json` (name/version/description/author), `.claude-plugin/marketplace.json`, `hooks/hooks.json`, `hooks/register.ts`, `config.json`. Dir modes 0700; files 0644 (config via PrivateFile). Unchanged files are left alone "Claude Code watches the folder" (66-67).
- `hooks/hooks.json` is exactly `{ "modules": ["./register.ts"] }` (`Resources/ClaudePlugin/hooks/hooks.json:1`; `ClaudePlugin.swift:982-985`). This is Claude Code's engine "modules" API: `import type { EngineInterface, Register } from 'claude-code'` (reg:1), `export const register: Register = (on) => {...}` (reg:672). Tests run with `claude plugin test` using `claude-code/testing` (ClaudePlugin.swift:10; `Resources/ClaudePlugin/tests/relay.test.ts:1-3`).
- Names: `fjord` / marketplace `fjord` (id `fjord@fjord`), dev builds `fjord-dev`; guest copy `fjord-guest` / `fjord-guest-dev`; legacy guest id `fjord@fjord` is uninstalled when found (ClaudePlugin.swift:15-36). The guest plugin has its own name because Claude Desktop copies the Mac's local `fjord` plugin into SSH sessions as a `--plugin-dir` without hooks, which would override an installed plugin of the same name (ClaudePlugin.swift:29-31).
- Version = app version + "r" + first 4 bytes of SHA-256(register+hooksJSON+marketplaceJSON) (ClaudePlugin.swift:23-27).
- Installation uses Claude Code's own CLI, NOT edits of settings.json: `ClaudePluginInstaller` (ClaudePlugin.swift:1071-1219) runs the Claude Code binary bundled in the Claude app (`binary` from `RouterStatus.findDefault()`, Router.swift:~190, `Status.noClaudeCode` "the copy the Claude app bundles wasn't found", 1076-1078) with:
  - `plugin list --json`, `plugin marketplace list --json` (1163-1169)
  - `plugin marketplace add <folder> --scope user` (1133), `plugin marketplace remove <name>` (1130/1159)
  - `plugin install fjord@fjord --scope user` (1136), `plugin update ... --scope user` (1141, then re-checks version, 1142-1145), `plugin enable ... --scope user` (1148), `plugin uninstall ... --scope user` (1128/1156)
  - Run through `OneShot` under `/usr/bin/env -i` with clean env (HOME, PATH=/usr/bin:/bin:/usr/sbin:/sbin, LANG, USER, LOGNAME, TMPDIR), cwd = home, timeout 120 s, runs tracked and killed on app quit (1201-1218, `PluginRuns.shutdown` 1245; Router.swift:229-233).
  - Status: `installed` / `notInstalled` / `outdated` (other folder, disabled, or installed cache version != shipped) / `noClaudeCode` (1072-1111). Folder marketplace is "read in place, so a new version of the sources reaches sessions on their next start (or /reload-plugins)" (1068-1070).
- Switch lifecycle (`SF/Router.swift:132-290`): `setRouterEnabled` -> `applyRouterSwitch`: on = advance key fence, `ClaudePlugin.write`, `ensureKey` (relay.key, 32 random bytes hex, mode 0600, outside the plugin folder because "Claude Code copies an installed plugin's folder into its cache" ClaudePlugin.swift:44-47, 72-82), install plugin; at launch only reinstall if outdated/missing (Router.swift:164-165). Off = `RelayKeyFence.revoke` deletes the key and every presence file immediately (ClaudePlugin.swift:1256-1287), then plugin + marketplace uninstalled.
- `config.json` fields given to the plugin because "a hooks module can't read the environment": `keyPath`, `presenceDir`, `sessionsDir` (= `~/.claude/sessions`, Claude Code's process registry), `inboxDir` (ClaudePlugin.swift:48-56; reg:202-208).

### 1.4 Relay protocol (what is on the wire / on disk)
Signed message (reg:9-12, `RelaySigner.sign` ClaudePlugin.swift:1023-1029):
```
⟦fjord v1 <target CLI session id> <nonce uuid lowercase> <ms since 1970> <hex HMAC-SHA256>⟧\n<base64(body UTF-8)>
```
MAC = HMAC-SHA256 keyed with the UTF-8 of the key's hex text, over `"v1\n<target>\n<nonce>\n<ms>\n"` + body bytes (reg:151-152; ClaudePlugin.swift:1059-1063). Base64 is used so "the peer channel's escaping and any Unicode normalization can't touch" the bytes (reg:9-10). Checks in `vet` (reg:442-466): parse, key present, MAC equal (constant time), target == `$.session.id()`, |now-ts| < 10 min (`WINDOW_MS`), valid UTF-8 (BOM preserved), nonce never claimed (`$.store` key `nonce.<nonce>`, pruned by window). Replays => "already delivered". HMAC is hand-implemented on SubtleCrypto SHA-256 (reg:92-99) because that is the environment's only digest.

Three ways in, "one check" (reg:14-17, 46-66):
1. Inbox (direct, no model): Fjord writes the signed text to `~/Library/Application Support/Fjord/relay/<session id>/<nonce>.msg` (dot-file renamed atomically, `RelayInbox.place` ClaudePlugin.swift:1441-1463, private mode 0600/dir 0700); plugin polls every 500 ms (`POLL_MS`, reg:76), runs the check, submits, writes `<nonce>.ack` = `ok` or `refused: <why>`; Fjord reads ack (empty file = not yet), deletes both (plugin can't delete). Fjord waits 6 s (`RelayInbox.wait`, 1410) then withdraws the .msg and treats fate as unsure. Leftovers older than 15 min swept (1412, 1513-1521). A poll stuck >5 s is abandoned (reg:594-597). Deliveries are serialized per session to keep order; ack written only after the engine accepted the words (reg:468-486, 638-661).
2. Peer-channel envelope to a running session: the Claude app wraps the text as `<cross-session-message from="…" name="…">\n<body>\n</cross-session-message>`; `session.receive` unwraps (`unwrap` reg:141-148) and answers by writing the ack into the inbox folder (reg:694-722).
3. First prompt of a sleeping session the app starts: `prompt.submit` rewrites it to just the words, guidance -> `context` (reg:719-742, 754-773). A slash command or empty body is dropped (`unsubmittable` reg:551-554, `{drop: 'Fjord: ...'}`).
Forgeries (bad signature) get no ack (only `signed:true` refusals are answered, reg:439-441, 508-513).

Control messages (inbox only; never over the peer channel):
- `abort-v1`: `⟦fjord abort v1 <target> <nonce> <ms> <nonce of delivery> <mac>⟧`, MAC over `"abort-v1\n<target>\n<nonce>\n<ms>\n<cancels>\n"` (reg:101-111; `signAbort` ClaudePlugin.swift:1034-1040). Plugin answers `ok before-start | aborted | together | too-late | unknown` (reg:19-37, 386-411). "aborted" = tool calls cut first (`tool.call` race, reg:316-323) then `$.turn.abort`; late task-notifications of cut tool-use ids are dropped for 1 h (`QUIET_MS`). A process Bash command itself runs on ("no hook can stop it", reg:32-33). Words stay in history: "Claude Code has no way to take a submitted prompt back out" (RouterCancel.swift:6; reg:37-38).
- `carry-v1`: `⟦fjord carry v1 <carrier session> <nonce> <ms> <local_<uuid> of target> <mac>⟧\n<base64(signed inner message)>`, MAC over `"carry-v1\n<carrier>\n<nonce>\n<ms>\n<local>\n"` + inner bytes (reg:46-55, 113-133; `signCarry` ClaudePlugin.swift:1047-1055). The CARRIER's plugin writes `<nonce>.taken`, checks `<nonce>.withdrawn` (race-free handshake, reg:570-576; ClaudePlugin.swift:1384-1385), then calls **the Claude desktop app's own MCP tool**: `$.mcp.call('ccd_session_mgmt', 'send_message', { session_id: <local_ id>, message: <inner signed text> })` (reg:582). No model turn in the carrier. Acks: `ok <app text>`, `refused: ...` only when the app's text starts with `Message not delivered:` (`NOT_HANDED_OVER`, reg:592), else `unsure: ...`; a carrier refuses to carry to itself and only carries a validly signed message for another session (reg:565-567).

Presence / lease (reg:213-257, 259-263): per session file `plugin-sessions/<cli session id>` = `{state:'live', sessionId, pid, startedAt, keyId (first 16 hex of SHA-256 of key), renewedAt, activation, capabilities:['inbox-v1','abort-v1','carry-v1'], turn: {id, startedAt}|null}`. Looked up by reading Claude Code's own process registry `~/.claude/sessions/*.json` (fields `sessionId`, `pid`, `startedAt`; also `hostSessionId`, `name`, `entrypoint`, `status`, `updatedAt` used by Fjord: RouterMCP.swift:865-894, RouterCarry.swift:96-103). Fjord counts a presence only if: state live, keyId == current key, renewedAt within 30 s (`lease`), file name == sessionId, pid alive (`kill(pid,0)`), and the registry still lists that pid with same sessionId+startedAt (ClaudePlugin.swift:154-188). Renewed every 10 s and at every turn start/complete. A `/clear` (new session id without session.start) is covered by re-reading the registry when id/key changes (reg:216-221). Fjord also uses `turn` to decide running/idle ahead of file guesses (Claude.swift:1202-1224).

### 1.5 Direction, payload, latency, idempotency (delivery of messages to sessions)
`SF/RouterCarry.swift` (not in my file list but it is the orchestrator; read lines 1-140): Every message of the user's goes the same way, running or sleeping ("docs/design/claude-channel.md"): Fjord persists a `DeliveryOperation {nonce, target CLI id, bodyHash, state waiting|sent|unsure|refused|needsYou, route carried|direct|opened, carrier, reason, local_ id, ...}` (kept 500) and waits for the write to reach disk BEFORE ordering (claude-channel.md:67-70); picks a carrier = a local session with `entrypoint == "claude-desktop"` in the registry, plugin presence with `carry-v1`, not the target, idle first then most recently updated (RouterCarry.swift:96-111); tries up to 2 carriers (`attempts`, 122); waits: carrier "taken" 6 s, running target ack 45 s, cold start 90 s, opened-in-app 60 s (RouterCarry.swift:~64-75). Plan: carriers exist and target plugin can `carry-v1` -> carry; target running but no carrier -> `direct` (its own inbox); no process and no carrier -> `open` (opens `claude://claude.ai/epitaxy/<id>` via `Claude.open`, Claude.swift:95-97, then uses its inbox) (RouterCarry.swift:114-123, RouterRun.swift:540-545). A session with a process but no plugin is NEVER sent to ("would read the message as a peer's", RouterRun.swift:522-526). A sleeping session (no process, single cliID) is signed for without its plugin being up, "the app starts it with the message (its plugin comes up with it)" (RouterMCP.swift:1023-1029, RouterPrepare.swift:346).
- "Sent" is only what the TARGET's plugin acks; the app's receipt "not delivered ... did no turn" for a consumed message is ignored (claude-channel.md:72-75, 85-91). Unsure is resolved by a late ack found at next launch, never by resending (claude-channel.md:68-72, ClaudePlugin.swift:1380-1383).
- Messages are shown to the model as the person's own words (`asUser:true`) and the app shows them as an ordinary user message (claude-channel.md:23-24, verified live per 106-113).
- Fjord appends pills' blocks after the words: `RouterPointers.attach(tagged, to: ready.text)` (RouterMCP.swift:958), an `@router` aside blocks the send (`noAside`, 803-808).
- Fjord's guest path (SSH computers): signs with the guest key read through the Silo file client, uses the guest clock (`GuestClock`), and writes to the guest inbox; requires `inbox-v1` presence in the guest (RouterMCP.swift:959-982; RouterCancel.swift:28-56).

### 1.6 Failure modes handled
- No Claude Code binary found / CLI error: `Failure("Claude Code wasn't found (the Claude app bundles it).")` (ClaudePlugin.swift:1121); CLI non-zero exit => message with stderr (1191-1195); install version mismatch after update (1143-1145).
- Key missing/changed: reload bounded 2 s (RouterMCP.swift:914-933, 994-1003); "Fjord couldn't sign ... plugin key is missing".
- Plugin disabled/unloaded: lease expiry 30 s; presence of an ended/crashed process fails the registry+pid check (ClaudePlugin.swift:154-188).
- Inbox: unanswered in 6 s -> withdrawn + `unanswered` (1493-1509); cancelled Task leaves fate unknown (1499-1504).
- Cancel: needs `abort-v1` presence under the current key (`Store.supportsAbort` ClaudePlugin.swift:1529-1541); unknown after a plugin reload (RouterDecisions.swift:74-92).
- Hook-dropped / engine-rejected words => `refused: not submitted: <why>` (reg:337-356, 470-486, 758-772).

## 2. THE FORM / PERMISSION HOOK (questions, plans, permission awareness): the one place settings.json is edited

### 2.1 What the user sees
Questions Claude asks (`AskUserQuestion`) and plans to approve (`ExitPlanMode`) appear in Fjord's Router brief and can be answered there (buttons/options, or in words judged by Jev); the answer arrives in Claude as if clicked in the app. Also "Asks your OK to <action>" shows for any other tool's permission prompt, read-only (the brief marks it "Waits for a permission... which only Claude can grant: open it to allow or deny", RouterBriefView.swift:382, 669). The Router never answers ordinary permissions for you.

### 2.2 Mechanism
- Claude Code hook event: **`PermissionRequest`** (only that one) in `~/.claude/settings.json`, entry `{"matcher": "*", "hooks": [{"type":"command","command": "<~/.claude/hooks/fjord-form.sh>", "timeout": 86400}]}` (Forms.swift:644-647, 702-703, 642). Dev builds use `fjord-dev-form.sh` (Forms.swift:636).
- Script `~/.claude/hooks/fjord-form.sh` (0755): `#!/bin/sh; [ -x <Fjord exe> ] || exit 0; exec <Fjord exe> --form-hook` (Forms.swift:661-671). So Claude Code spawns the Fjord app binary in `--form-hook` mode (`FormHook.main`, Forms.swift:346-356).
- Install/uninstall: `FormHookInstaller` (Forms.swift:608-803) edits settings.json via `ClaudeSettingsFile.modify` (read -> compute -> re-read -> atomic replace; 3 attempts; keeps file mode; follows a symlink to its target; refuses invalid JSON / non-object / unexpected `hooks` shape; `SF/ClaudeSSHSettings.swift:1-50`). **Backup**: first time Fjord changes an existing file, a copy `~/.claude/settings.json.fjord-backup` is written (never overwritten) (Forms.swift:639, ClaudeSSHSettings.swift:44-46; `ClaudeSSHSettings.swift:115-116` reuses the same backup name for SSH settings). Fjord's entry is identified by the command path; an older entry under another matcher is replaced, other users' hooks sharing the entry stay (Forms.swift:697-706, 739-748). Uninstall removes only Fjord's entry and the script (715-725). The script is removed if install fails and wasn't there before (709-711). On launch the hook is reinstalled only if outdated (Router.swift:~190).
- Enable marker: `~/Library/Application Support/Fjord/forms/.enabled`; without it the hook exits 0 at once (`FormBridge.setEnabled`, Forms.swift:175, 287-295; hook check 390, 434). Folder 0700.
- Hook protocol (`FormHook.run`, Forms.swift:384-438): reads the PermissionRequest JSON on stdin (60 s read limit, 8 MB; signals SIGTERM/INT/HUP => stop). Requires `hook_event_name == "PermissionRequest"`, `tool_name`, `tool_input`.
  - For `AskUserQuestion` / `ExitPlanMode`: writes `forms/<session>-<ms>-<pid>.json` = `{key, session_id, transcript_path, cwd, tool_name, tool_input, created_at, pid, tool_use_id?}` then WAITS (poll 0.25 s, max 24 h) for `forms/<key>.answer.json`. When found prints on stdout `{"hookSpecificOutput":{"hookEventName":"PermissionRequest","decision":{...}}}`:
    - question: `{"behavior":"allow","updatedInput": <original input with "answers": {questionText: answerText}>}` (Forms.swift:474-477). Answer file shape `{"answers": {question: text}}`; any text accepted ("the form always offers Other"); multi-select answers joined ", " (Forms.swift:242, 251-272).
    - plan approve: `{"behavior":"allow","updatedInput": <input as it came>}` (a bare allow is ignored for this tool, Forms.swift:312); keep planning: `{"behavior":"deny","message": rejected | rejectedWithNote + note}` with Claude Code's exact rejection sentence (Forms.swift:318-319, 471-473). Answer file `{"plan":{"approve":Bool,"feedback":String}}` (274-281).
  - Leaves silently (prints nothing; Claude's own form stands) if: the call's `tool_result` shows up in the session transcript (answered in the app; `TranscriptWatch` follows `transcript_path` JSONL, matches the last `assistant` `tool_use` of that tool whose `input` equals the form's input, then waits for a `user` `tool_result` with that `tool_use_id`; Forms.swift:484-601); the parent process is gone (`getppid()==1`); signalled; marker removed; 24 h timeout.
  - For any other tool: `observe` writes `permissions/<session>-<ms>-<pid>.json` `{key, session_id, transcript_path, tool_name, tool_input, created_at, tool_use_id?}` and exits at once, prints nothing (Forms.swift:446-463). Fjord (Claude.swift:209-330, 411-575, 1096-1121) watches `permissions/` (FSEvents-style `FolderWatcher`, 0.2 s) and merges the note with the transcript tail to show "Asks your OK to ..." until the tool's result appears; `ClaudeProcesses.swift` checks whether an approved Bash command is already running as a child of the session's process to clear the note.
- Fjord side: `FormBridge` (Forms.swift:155-301) watches `forms/` (`FolderWatcher` 0.1 s), decodes into `PendingForm` (session id, transcript path, questions/options, plan Markdown, hook pid, `toolUseID`), newest form per session; forms whose hook pid is dead are deleted. `FormWriter` writes the answer atomically with `renamex_np(RENAME_EXCL)` (first answer wins; claim list of 1000; gate re-checked on main actor at the rename) (RouterMCP.swift:1085-1186). `FormSnapshot` (RouterFormReply.swift:104-123) binds a judgment to the exact form id + tool_use id so a changed form is never answered by an old judgment.
- Words answering a form/plan (RouterFormReply.swift:1-102): `planDecision` asks Jev (TypeSafe classifier via `CardJudge`, key required) "does the message approve the plan as it is"; >= `CardJudge.sure` approves else sends back with the message as feedback; nil (no key/timeout) leaves the plan waiting. `askFormAnswers` maps a typed message to one option per question (opaque ids o1..), multi-select as yes/no per option, "other" only for a one-question form (answer = message); bounds 8 questions, 12 options, label 120, description 300, question 300 chars; all-or-nothing; session-written text fenced with `SessionFence`.
- Guest (SSH) variant: `GuestRouterInstaller` (not in slice) writes the same plugin files plus a Node form hook (`paths.hook`, `paths.formModule`), merges the same `PermissionRequest` entry (matcher `AskUserQuestion|ExitPlanMode` only, `GuestClaudeSettings.matcher = FormHookInstaller.formMatcher`) into the GUEST's `~/.claude/settings.json` with a first-original backup (GuestRouterInstaller.swift:195-250, 340-380); requires Node >= 18 (provisions one) and git in the guest PATH (lines 40-60).

### 2.3 Failure modes
Disabled marker / dead hook / answered in app => hook leaves; invalid or odd settings.json => Fjord leaves it alone and says so (Forms.swift:615-631: invalid JSON, not an object, unreadable, `hooks`/`hooks.PermissionRequest` wrong shape, kept changing); `Status.outdated` when the app moved (command path differs) (609-613).

### 2.4 Constraints
Claude Code 2.1 behaviour checked: Approve=`allow` with the input as came; Keep planning=`deny` with Claude's own words (Forms.swift:312-313). The timeout of 86400 s keeps Claude waiting on the hook for up to a day. ## 3. The Router's own MCP server (`SF/RouterMCP.swift`): how Fjord exposes tools to its own `claude -p` runs
- Not an MCP server for user sessions. It is a tiny HTTP/JSON-RPC server (own `MiniHTTP`, lines 9-86; `RouterRPC` 91-194; `RouterMCPServer` 201-461) on `127.0.0.1:<system-picked port>`, one start per Router run, Bearer token = 32 random bytes hex, path `/mcp`, POST only; limits: 8 connections, 10 s per request, 60 s idle, 16 KB header, 1 MB body, batch <= 16, response <= 1 MB. Methods: `initialize` (serverInfo name `fjord`, capabilities tools only, protocolVersion echoes the client's else 2025-06-18), `ping`, `tools/list`, `tools/call` (RouterMCP.swift:162-180). Unknown tool => JSON-RPC error -32602.
- `--mcp-config` file written to `~/Library/Application Support/Fjord/router/mcp-run-<uuid>.json` (0600, deleted after): `{"mcpServers":{"fjord":{"type":"http","url":"http://127.0.0.1:<port>/mcp","headers":{"Authorization":"Bearer <token>"}}}}` (RouterMCP.swift:453-460; RouterRun.swift:181-199).
- The run is a headless Claude Code process: `claude -p --model <model> --tools "" --mcp-config <cfg> --strict-mcp-config --allowedTools mcp__fjord --setting-sources "" --no-session-persistence --output-format stream-json --verbose --include-partial-messages --json-schema {reply,done} --append-system-prompt <role>`, cwd = `Fjord/router/`, task context on STDIN, timeout `RouterRun.timeout` (RouterRun.swift:134-141, 195-206). Model Haiku (RouterRun.swift `model`); other `claude -p` users: `RouterBrief.swift:31`, `RouterProjectDecide.swift:299-306` (Sonnet, `--tools "" --strict-mcp-config --setting-sources ""`), `RouterProjectProposal.swift:986, 1096`.
- Tool names exposed in the schema list: `RouterTools.specs = [board, answer] + FjordTools.specs` (RouterMCP.swift:589). The per-run allowed subset comes from `RouterCapability.toolNames(intent, triage:)` (RouterRun.swift:102-109, 185-187); the model sees them as `mcp__fjord__<name>` (`toolPrefix`, RouterRun.swift:236).
  - `board`: no args (`additionalProperties:false`); returns JSON: `entries` (thread key, kind, title, project, question fenced, age, options, plan/form details, session fields), `working`, `recent`, `projects`, `brief` (RouterMCP.swift:591-595, 703-745). All session text is fenced with `<session-content>` via `SessionFence` and cleaned/bounded with `UntrustedText.clean`.
  - `answer`: `{thread: string, option: integer>=1}` both required (597-604). Clicks the brief's option button via `briefs.answer`; refuses `words`: "an answer in words is the user's to send" (788). Gated by `live(ticket)`: only on a user turn (`turnText != nil`), Router enabled, agents enabled.
  - `FjordTools.specs` (SF/RouterFjord.swift:64+; ALL of these change Fjord's own settings, not Claude): `list_categories get_category create_category update_category delete_category reorder_categories list_groups create_group update_group delete_group list_inbox explain_entry mark_entries get_settings set_setting list_known` (grep of `Tool(name:`). Tool spec format `{name, description, inputSchema}` from `JSONShape` fields.
- IMPORTANT: no MCP tool sends words to a session. Words go only through the signed plugin path above. Retained legacy code in the same file: `RouterTools.prepare`/`approveSend`/`prepared` (RouterMCP.swift:947-1066) which "prepare" a signed message and approve a `SendMessage` tool call "natively" (Claude's permission prompt answered over stdin) if the text equals the prepared bytes exactly; today `RouterSender` states "No Claude Code process and no model is run for it" (RouterRun.swift:436-440). INFERRED: `approveSend` is vestigial for the old headless `--tools SendMessage` sender removed per claude-channel.md:52-55; `RouterStream.permission`/`permissionLine` (RouterStream.swift:18, 66-69, 106-111) still parse stream-json `control_request` `can_use_tool` and answer `control_response` (`behavior allow/deny`, `updatedInput`). Whether any live path still uses them was not confirmed.
- Reading peer messages in stream-json: `<cross-session-message from-name=…>` parsed by `RouterStream.peer` (RouterStream.swift:89-103).
- Targets resolution reads `~/.claude/sessions/*.json` (`hostSessionId`, `sessionId`, `pid`, `name`) = Claude Code's registry; `hostSessionId` is the Claude app's id (`local_<uuid>`) mapped to Claude Code `sessionId` (RouterMCP.swift:865-894, 829-862).

## 5. "Handing GitHub items to a session" (InboxActions.swift, 1514 lines; read relevant parts + grep)
- User sees: in Triage a category can have a "Send to the Router" action (`ActionKind.askRouter(prompt: ActionPrompt)`, InboxActions.swift:14-20) that runs "when a thing enters" or "for each new fact" (ActionTrigger 11-16). Chips on rows: "session started", "sent to <session title>", "waiting on you in the Router", "Open the session in Claude" (InboxActions.swift:786-810, ActionPrompt.swift:161).
- Mechanism: the action does NOT talk to Claude directly. `StoreActionPerformer.sendToRouter` (InboxActions.swift:~1436-1450) composes the prompt (`composeForRouter`), tags the notification, sets `context.action = RouterActionSource(origin: SessionOrigin(category, thing title ≤80 chars, actionID, runID))`, and submits through `store.routerDispatcher.submit` as the user's own message from the category (ActionPrompt.swift:3-6, 144-149; InboxActions.swift:866-870). The dispatcher then either sends to a session working in the thing's repo or STARTS a session in a local clone (`LocalClones`, CodeFolders `clones(of:)`), or waits for the user ("RouterDispatcher"); starting a session is handled outside my slice (the app-started session path uses `claude://resume` per claude-channel.md:33, 58, router-redesign.md:10).
- GitHub text is wrapped for the model via `UntrustedFence.github` (`<github-content untrusted="true">` + warning) and neutralised so it cannot close the fence (UntrustedText.swift:30-55; ActionPrompt/InboxActions `RouterPointers.notification(...)` block). The action message "is unattended": goes only to a session, never to the Router's own runs; if unsure where, it waits for the user (ActionPrompt.swift:144-146).
- Gating: runs only while Triage and the Router are both on (`toolsLinked`, InboxActions.swift:1219-1224, 1434-1438); waits for routing readiness = Claude sessions read (`claudeReadAsked`/`claudeReadOnce`) and code folders scanned (`routingReady`, 1228).
- Previews (Try on latest match) state "It goes to the claude.ai project or thread its pill names" vs "The Router sends it to the claude.ai project or thread it is for; if unsure, it asks you." (InboxActions.swift:906-908).
- `session(folder, prompt:)` legacy action kind decodes to `askRouter` (28-37).
- Other action kinds (`comment`, `rerun`) use the GitHub API only (`store.gh`), no Claude.
